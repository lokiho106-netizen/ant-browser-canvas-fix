# 调查与验证记录

## 两类故障需要分开

此次排查先出现了 `ERR_CONNECTION_CLOSED`，后出现 `Crashpad_NotConnectedToHandler`。

前者在独立网络请求经过同一代理时也能复现 TLS 握手失败，绕过该代理则能访问，说明需要检查代理路径。后者是浏览器页面进程故障；Crashpad 错误表示未连接到崩溃报告处理程序，不能单独用来判断崩溃根因。

页面崩溃并不能证明网站主动封禁了浏览器指纹。应通过保持其他条件不变的对照测试，分别检查网络与内核行为。

## 内核问题的证据

Windows x64 的本地测试中，同一 `150.0.7871.186` 内核在默认配置下能够加载目标页面，开启指纹模拟后多个独立配置无法完成加载；更换种子、关闭 GPU 也未解决。相同指纹参数访问其他页面可以成功。

随后找到上游同版 Canvas 崩溃报告，并核对本地 DLL 的完整哈希和相关指令。修正后的副本保留了指纹模拟参数，能够完成此前失败的页面加载。

这组本地对照结果支持内核缺陷这一解释。测试超时本身不等同于取得了崩溃堆栈；根因判断同时依赖用户看到的页面崩溃、上游报告、文件匹配和修复前后的行为差异。

## 指令修复说明

上游问题定位到 Canvas 像素邻行指针计算：错误路径使用了未按行跨度计算的行索引，可能读到像素缓冲区之前。Windows 这一精确构建中，临时修复把 `add r8, rax` 改成 `mov r8, rdx`，使用已经算好的当前行指针作为邻行计算基准。

文件偏移和指令只适用于 README 列出的完整文件哈希。本项目没有对任意版本执行特征扫描、猜测偏移或关闭指纹功能。

原始问题及指令修复来源：[fingerprint-chromium #94](https://github.com/adryfish/fingerprint-chromium/issues/94)；相关 Windows 报告：[问题 #95](https://github.com/adryfish/fingerprint-chromium/issues/95)。维护者在 #94 中确认计划修复。本项目的本地工具不能替代上游正式版本。

## 共享内核的含义

Ant Browser 的多个实例可以引用同一个内核目录。修复那一份 `chrome.dll` 后，所有使用该目录的实例会在下次启动时加载修复文件；新建实例引用同一目录时也会受益。

另一个目录中的 DLL 不会因此自动改变。浏览器更新、重新下载内核或覆盖安装会替换文件，因此应用本地补丁后仍应根据完整哈希识别状态。
